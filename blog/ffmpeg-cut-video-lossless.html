FFmpeg 无损剪辑视频教程（不重新编码，秒级完成）

发布：2026年5月26日  |  适用：Windows / Mac / Linux

什么是"无损剪辑"？

普通视频剪辑软件（如剪映、PR）在导出视频时，无论你改动多小，都会重新编码整段视频。一个 1GB 的视频，仅剪掉片头 10 秒，导出可能花 10 分钟，画质还可能有损失。

FFmpeg 的无损剪辑（Lossless Cut）原理是：不重新编码，只复制原始数据流，仅裁剪你需要的片段。速度极快——几十 GB 的视频几秒内完成，且画质与原片完全一致。

适用场景：

  • 剪掉视频片头片尾
  • 删除中间广告片段
  • 将长视频拆分成多个片段
  • 从录播中提取精彩部分

基础无损切割命令

按起止时间剪切

从一个视频中提取第 30 秒到第 5 分钟之间的内容：

ffmpeg -ss 00:00:30 -i "input.mp4" -to 00:05:00 -c copy "output.mp4"

参数说明：

  • -ss 00:00:30：起始时间（第 30 秒开始）
  • -i：输入文件
  • -to 00:05:00：结束时间（到第 5 分钟停止）
  • -c copy：关键参数——复制所有流而不重新编码

使用 -t 指定持续时长

如果知道要截取的时长而非结束时间，用 -t 更方便：

ffmpeg -ss 00:00:30 -i "input.mp4" -t 00:04:30 -c copy "output.mp4"

以上命令同样从第 30 秒开始，截取 4 分 30 秒的内容。

-ss 放前面还是放后面？

-ss 放在 -i 前面（输入前定位）和后面（输出前定位）有本质区别：

# 方式A：-ss 在 -i 前面（快速，基于关键帧，可能有偏差）
ffmpeg -ss 00:01:00 -i "input.mp4" -to 00:03:00 -c copy "output.mp4"

# 方式B：-ss 在 -i 后面（慢，但精确到帧）
ffmpeg -i "input.mp4" -ss 00:01:00 -to 00:03:00 -c copy "output.mp4"
  • 方式 A：FFmpeg 先跳到最近的关键帧开始解码，速度极快，但起始位置可能偏移 1~5 秒（取决于关键帧间隔）
  • 方式 B：从开头解码到指定位置，起始位置精确，但速度较慢

多数场景下，方式 A 就足够精确，尤其是剪片头片尾这种不要求帧级精度的情况。

同时剪切多个片段

如果你想保留第 1~3 分钟和第 8~10 分钟，删除中间的广告部分，可以分别执行两次命令。批量处理可用脚本：

# Windows 批处理（保存为 cut.bat）
@echo off
ffmpeg -ss 00:01:00 -i "%~1" -to 00:03:00 -c copy "%~n1_part1.mp4"
ffmpeg -ss 00:08:00 -i "%~1" -to 00:10:00 -c copy "%~n1_part2.mp4"
echo 剪辑完成

按文件大小分割视频

如果你需要将一个长视频按大小分成几段（例如上传到有大小限制的平台），可以用 segment 参数：

ffmpeg -i "input.mp4" -c copy -map 0 -segment_time 00:10:00 -f segment -reset_timestamps 1 "output_%03d.mp4"

以上命令每 10 分钟切一段，生成 output_001.mp4、output_002.mp4 等文件。

常见问题

剪切后开头几秒画面卡住？

这是因为起始位置不在关键帧上。解决方法：将 -ss 放在 -i 之后（方式 B），或略微调整起始时间到上一个关键帧。

剪切后音画不同步？

部分视频的关键帧间隔不均匀。添加 -avoid_negative_ts make_zero 参数可修复此问题：

ffmpeg -ss 00:01:00 -i "input.mp4" -to 00:05:00 -c copy -avoid_negative_ts make_zero "output.mp4"

能用 FFmpeg 剪切 M3U8 下载的 TS 文件吗？

完全可以。命令完全一样。如果 TS 文件是先合并再剪辑，建议先合并 TS 文件再用本教程的方法剪切。

到底损失画质吗？

使用 -c copy 的剪切完全不损失画质。FFmpeg 只是把原始编码数据从输入文件复制到输出文件，中间不做任何编解码。唯一的小限制是：起始位置只能在关键帧上（方式 A），但画质本身没有变化。
